上传说明 — auramind.cloud（ITAD + 隐私声明）
================================================
生成日期: 2026-10-09
包含文件: 18 个（见文件末尾清单）


⚠️ 第一步：先部署 Worker（顺序不能颠倒）
------------------------------------------------
worker/src/index.ts 属于本仓库（要一起上传），但它**不会自动生效** ——
后端跑在 Cloudflare（api.auramind.cloud），必须单独部署：

    cd worker
    npm ci
    npm run check
    npm run deploy

为什么必须先做：新版 Worker 兼容旧前端，**旧 Worker 不兼容新前端**。
如果先前端后 Worker，访客在表单里选 ITAD 提交会收到 400 失败。

部署后可验证：

    curl https://api.auramind.cloud/health      # 应返回 {"status":"ok"}


第二步：把这些文件合并到仓库
------------------------------------------------
本包保留了目录结构，直接解压覆盖到你的 clone 根目录即可，例如：

    # Windows PowerShell
    Expand-Archive auramind-upload.zip -DestinationPath "C:\你的clone" -Force

    # 或 macOS / Linux
    unzip -o auramind-upload.zip -d /path/to/clone

注意：

1. 不要整目录替换 —— 你的仓库里还有其他未变更的文件（public/、components/ 等）。
2. 本包**不含** package-lock.json、worker/package-lock.json，因为本次未变更它们。
3. 本包**不含** .github/workflows/nextjs.yml，因为它本次未修改，保持仓库现状。


第三步：删除一个旧文件（必须）
------------------------------------------------
    git rm components/sections/BusinessIntegration.tsx

必须删。它的内容已并入 Services.tsx；保留会导致板块重复，
而且其中「AI Market Research & Intelligence」是你内部已判定不再提供的业务。


第四步：本地自检
------------------------------------------------
    npm ci
    npm run lint      # 期望 exit 0
    npm run build     # 期望成功，路由含 / 与 /privacy


第五步：提交并推送
------------------------------------------------
    git add -A
    git commit -m "新增 ITAD 业务线、PDPA 隐私声明与表单同意；移除已否决的 AI Market Research"
    git push

推送后 GitHub Pages 会自动重新部署。


第六步：验收
------------------------------------------------
    node tools/verify-deploy.mjs

期望 9/9 通过（exit 0）。当前线上是 3/9 —— 因为前端还是旧版。

再手工做一次端到端测试（脚本不会替你提交表单）：
  在网站上选择 ITAD，提交一笔测试询价；
  确认返回成功，且 info@auramind.cloud 收到含「Privacy consent」行的邮件。

  - 新增 app/privacy/page.tsx 隐私声明页
  - 表单新增同意勾选，未勾选无法提交
  - 记录 consentGiven / consentVersion / consentAt
  - 页脚新增 Privacy Notice 链接

移除
  - components/sections/BusinessIntegration.tsx（含已否决的 AI Market Research）

工程
  - next.config.ts 新增 trailingSlash: true（/privacy 需要）
  - 新增 .gitignore（原仓库没有）
  - 新增 tools/verify-deploy.mjs（部署后 9 项核验）
  - 新增 tools/secret-scan.mjs 与 .github/workflows/secret-scan.yml（CI 密钥门禁，默认仅手动触发）

导航修复（重要）
  - Header.tsx / Footer.tsx / sections/Hero.tsx 里的链接由纯锚点改为根相对：
      改前 href="#services"        -> 在 /privacy 页点击无反应
      改后 href="/#services"       -> 从任意页面都能回到主页并定位区块
    这是实测发现的缺陷：/privacy 页上点 header / footer 的 Services、About、
    Contact、logo 都不会回到主页。
  - 主页行为不变（仍是无刷新的同页跳转）。

Header 在非主页不再透明（重要）
  - 透明导航原本只在主页 hero 上成立。进入 /privacy 后没有 hero 可依托，
    但 Header 仍按「覆盖 hero」逻辑渲染成透明，导致文字与背景对比不足。
  - 现已按路由判断：仅 pathname === "/" 时启用透明态；其他页面固定使用
    实色导航（bg-auramind-elevated/92 + backdrop-blur-md + 底边框 + 阴影）。
  - 静态导出时 Next 会为每条路由预渲染，因此 /privacy 的 HTML 本身就带实色
    类名，不存在「先透明再变实色」的闪烁。
  - 实现采用 usePathname() 路由判断而非「挂载标志」，因为客户端跳转时该
    组件可能保持挂载（例如中键新标签页场景），挂载标志会留下错误状态。


两个前提，请确认
------------------------------------------------
1. GitHub 仓库 Variables 需已存在（构建时读取，缺失不会报错但表单会禁用）：
     NEXT_PUBLIC_PROJECT_INQUIRY_ENDPOINT
     NEXT_PUBLIC_TURNSTILE_SITE_KEY
   线上表单目前可提交，说明这两个值已配置。

2. ITAD 对外表述目前刻意保持保守 —— 未出现任何标准号、认证名、
   合作方名、设施名或回收率数字。若要加入 NIST SP 800-88、R2、
   e-Stewards 等字样，请先确认实际执行能力与资质，否则不要发布。
